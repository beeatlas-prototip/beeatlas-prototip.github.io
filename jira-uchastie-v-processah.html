Зачем

Архитектор системы приходит на страницу своего приложения с вопросом «в каких процессах оно участвует и какими методами»: кто-то вызывает метод, которого нет в архитектуре, или нужно понять, что заденет изменение функционала.

Вкладка уже собрана по встрече 06.10, но на встрече 07.10 обе таблицы переразобрали: в текущем виде они перегружены и показывают поля, которые на этой странице не разбирают.

Что нужно сделать

1Общее по вкладке

  • Вкладка называется «Участие в процессах», стоит перед «Связанные проекты».
  • Внутри переключатель (pill-toggle): «Шаги E2E-сценариев» и «Шаги Use Case». По умолчанию первый.
  • Поиск, сортировка и состояние раскрытых строк у разделов независимые: переключение раздела ничего не сбрасывает.
  • Раскрывашка — тем же паттерном, что на вкладке «Интерфейсы, методы и SLA» (шеврон в первой ячейке), а не новым компонентом.
  • Почему раскрывашка: у одного процесса или Use Case много методов приложения, у каждого свой ТВ и в будущем свой Dynamic. Плоской таблицей это дубли верхних строк и уход по ширине.

  • «Шаг», «Вызывающий», «Вызываемый» не нужны: кто кого вызывает, видно в карточке Use Case; здесь архитектору системы нужен перечень своих методов.
  • «Статуса вызова» не существует как сущности — это остаток раннего VISION.
  • «Описание» берётся из description вызова. У планируемого метода это постановка на разработку, текст большой: в ячейке он обрезан в одну строку, по клику открывается целиком в боковой панели, в панели кнопка «Скопировать описание». Из обрезанной ячейки текст не скопировать, а его забирают себе в задачу.
  • «Статус метода» — бейдж: РеализованПланируетсяНа ревью «На ревью» — метод планировался, но на него уже пришёл вызов: похоже, его сделали, и архитектор должен подтвердить.
  • Метод не кликабельный: карточки метода в системе нет, переход — отдельная история.

4Поиск

Фильтров в обеих таблицах нет, остаётся одна поисковая строка на раздел. Поиск фронтовый, по уже загруженным данным, без обращения к бэку.

Как ищет

  • Срабатывает по мере ввода, без кнопки и без Enter.
  • Регистр не учитывается, ищется вхождение подстроки в любом месте значения, а не совпадение с начала. Пробелы по краям запроса отбрасываются.
  • Пустой запрос — полный список.
  • Поиск идёт и по верхнему уровню, и по вложенным строкам: иначе найденного не видно, пока строка не раскрыта.

Где ищет

Плейсхолдеры: «Процесс, метод или техническая возможность» и «Use Case, метод, описание или техническая возможность».

Что показывает в выдаче

  • Строка верхнего уровня попадает в выдачу, если совпал её заголовок (название или код) или любой из её методов.
  • Совпало по заголовку → строка показывает все свои методы: пользователь искал процесс целиком.
  • Совпало только по методам → строка раскрывается автоматически и показывает только совпавшие методы.
  • Автораскрытие не запоминается: оно живёт, пока держится запрос. Строки, раскрытые пользователем руками до поиска, после сброса остаются раскрытыми.
  • Счётчик «Методов приложения» всегда показывает полное число методов, а не число совпавших: это характеристика процесса, а не результата поиска.
  • Сортировка применяется к результату поиска, а не к полному списку.
  • Ничего не нашлось → строка в теле таблицы: «Ничего не нашлось. Измени запрос или сбрось его».

Сброс

  • Крестик в правой части поля, появляется, когда в поле что-то есть. Очищает запрос, возвращает полный список и фокус в поле.
  • Отдельной ссылки «Сбросить» нет: сбрасывать, кроме запроса, нечего.

5Сортировка

  • Сортируются столбцы верхнего уровня: заголовок — кнопка, первый клик по возрастанию, повторный клик по тому же столбцу переворачивает направление.
  • Стрелка направления у активного столбца видна всегда, у остальных появляется на ховере с прозрачностью 38% (ДС).
  • Счётчик «Методов приложения» сортируется как число, а не как текст.
  • Пустые значения при сортировке по возрастанию уходят в конец.

6Отображение контента

  • Содержимое ячеек — в одну строку, обрезка по многоточию, полное значение в тултипе (ДС Table, «Отображение контента»).
  • Обрезка через white-space: nowrap, а не -webkit-line-clamp: 1: с клампом длинный путь метода переносится и обрезается сразу после «POST».

Критерии приёмки

  • Вкладка называется «Участие в процессах», внутри переключатель «Шаги E2E-сценариев» / «Шаги Use Case».
  • В разделе E2E на поверхности только процесс с кодом и счётчиком методов; раскрытие показывает Метод · ТВ · Dynamic View. Колонок «Шаг сценария», «Источник», «Интерфейс» нет, Dynamic View показывает «—».
  • В разделе Use Case на поверхности только Use Case с кодом и счётчиком методов; раскрытие показывает Метод · Описание · ТВ · Dynamic · Статус метода. Колонок «Шаг», «Вызывающий», «Вызываемый», «Статус вызова» нет.
  • Описание вызова открывается целиком в панели и копируется кнопкой.
  • Статус метода показан бейджем одного из трёх видов: Реализован, Планируется, На ревью.
  • Фильтров в разделах нет, есть одна поисковая строка со сбросом крестиком.
  • Запрос, совпадающий только с методом внутри строки, раскрывает эту строку и показывает в ней только совпавшие методы; запрос, совпадающий с названием или кодом строки, показывает все её методы.
  • После сброса поиска автораскрытые строки закрываются, а раскрытые руками остаются раскрытыми.
  • Запрос без совпадений показывает «Ничего не нашлось. Измени запрос или сбрось его».
  • Клик по заголовку столбца сортирует верхний уровень, повторный клик переворачивает направление; счётчик методов сортируется численно.
  • Длинные значения обрезаны в одну строку и раскрываются тултипом; таблицы не вызывают горизонтальный скролл страницы.
  • Переходы со строк работают: в E2E-сценарий, в Use Case (новая вкладка), в Dynamic-диаграмму. Метод не кликабельный.

Вне скоупа

  • Вкладка «Клиентские пути» — отдельная задача: на встрече решили, что она нужна, но срок не обсуждали, а правило вхождения (пути, которыми приложение владеет) и наличие данных на бэке ещё нужно подтвердить. В прототипе вкладка показана.
  • Карточка метода и переход с вызова. В системе её нет; обсуждали вариант открывать метод в дереве интерфейсов с предзаполненным поиском — не сейчас.
  • Редактирование привязок с вкладки: она только показывает.
  • Переход в карточку технической возможности.
  • Переделка фитнес-функции SC.01 — отдельная задача на тех же данных.

Открытые вопросы

  • Формулировки статусов метода. «Реализован / Планируется / На ревью» проговорены голосом: подтвердить значения и правило перехода в «На ревью» у архитектора платформы и автора модели.
  • Описание и статус метода в области поиска. На встрече перечислили процесс, метод и ТВ. Описание и статус добавлены сверх этого: описание — единственное место, где лежит постановка на метод, по нему удобно искать. Если не нужно, поиск по этим полям убирается.
  • Связка «шаг E2E → Dynamic View» на бэке. Пока её нет, колонка пустая; без неё переделанная SC.01 не посчитается.
